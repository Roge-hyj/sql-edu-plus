# 业务数据库迁移演练记录（2026-08-24）

## 结论

本次在隔离的临时 MySQL `8.0.46-0ubuntu0.24.04.3` 实例上完成了完整迁移、回退、再次升级、备份恢复和并发连接演练。

这次演练即为当前固定业务数据库版本的验收依据。判题层 Docker 使用的 MySQL 8.4 是独立执行器，不属于业务数据库迁移范围。

## 环境隔离

- 临时数据目录：`/tmp` 独立目录；
- 临时端口：`127.0.0.1:13307`；
- 临时数据库：`sql_edu_ci`；
- 恢复数据库：`sql_edu_restore`；
- 未连接或修改业务端口 `3306`；
- 演练结束后已停止实例并删除临时数据和备份文件。

## 结果

### 1. 升级到 head

```text
alembic upgrade head: PASS
head: g7h8i9j0k1l2
tables: 11
```

迁移包含完整链路：初始表、用户角色、聊天、题目字段、Q-matrix、Phase 3 学习状态、提交幂等、教学审计和验证码安全字段。

### 2. 回退与再次升级

```text
g7h8i9j0k1l2 -> f6a7b8c9d0e1: PASS
f6a7b8c9d0e1 -> g7h8i9j0k1l2: PASS
```

### 3. 备份恢复

使用 `mysqldump --single-transaction --routines --events --no-tablespaces` 完成备份。恢复库核对结果：

```text
tables_restored: 11
captcha_rows: 1
alembic_version: g7h8i9j0k1l2
```

第一次不带 `--no-tablespaces` 的备份被最小权限账号拒绝，因为需要 `PROCESS` 权限；改用 `--no-tablespaces` 后成功。生产发布手册已采用这一更小权限的备份选项。

### 4. 并发连接

恢复库执行 20 个并发连接查询，结果为 `20 concurrent connections: ok`。

## 范围说明

本次验收固定的是业务持久化数据库 MySQL 8.0.46。判题层可以继续使用 Docker 中的 MySQL 8.4、PostgreSQL 16、SQL Server 2022 和 Oracle 23ai；这些执行器有独立连接、schema 和生命周期，不复用业务库迁移。
