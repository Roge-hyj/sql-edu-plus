# SQL 智能教学系统 — 基于控制理论的闭环算法架构说明 (终极版)

本文档详细拆解了系统核心的四大算法模块：**AST 感知层**、**BKT 记忆层**、**变分控制策略**及 **A* 启发式搜索**。最后，通过控制理论将其串联为一个完整的闭环教辅架构。

---

## 1. 感知层：AST (Abstract Syntax Tree) 逻辑诊断算子

### 1.1 数学背景：图论与树形结构匹配
SQL 语句本质上是声明式的逻辑树。我们利用 **$f_{AST}$** 算子将代码从“字符串空间”映射到“逻辑语义空间”。
*   **结构提取**：将 $SQL_{student} \rightarrow Tree_s$，$SQL_{correct} \rightarrow Tree_c$。
*   **逻辑去噪**：通过树遍历算法，忽略大小写、空格及非功能性别名，提取核心子图。

### 1.2 核心逻辑：实质性断层检测
定义结构误差向量 $E_t$。系统检测 $Tree_s$ 相对于目标状态 $Tree_c$ 的节点缺失与分支偏差：
$$E_t = \{ (KP_i, Severity_i) \mid Node_i \in Tree_c, Node_i \notin Tree_s \}$$
这使得系统能够精确区分“语法噪音”与“逻辑断层”，为后续提示提供精准的靶向依据。

### 1.3 LLM 与 AST 的“高维协同”：自由推理与形式化约束
不同于将 LLM 仅作为“话术翻译官”的降维应用，本系统由于引入了 AST 算子，实现了 LLM 推理能力的**全量释放与精准校准**：

*   **自主推理与语义对齐 (Autonomous Reasoning)**：系统并不禁止 LLM 自由发挥。相反，我们将题目要求、学生 SQL 及 AST 特征共同交给模型。LLM 可以凭借其庞大的知识量，从业务常识、代码风格及深层语义（而不仅仅是结构）出发，自主寻找可能的逻辑漏洞。
*   **形式化验证护栏 (Formal Verification Guardrails)**：AST 算子在此扮演“物理定律”的角色。LLM 的每一个推理结论都会与 AST 产生的确定性误差向量 $E_t$ 进行交叉验证。
    *   **幻觉拦截**：如果 LLM “认为”某个子句有错但 AST 判定结构等价，系统将拦截该错误描述或提示 LLM 重新审视，从而在保留 LLM 动态发现错误能力的同时，彻底杜绝结构性幻觉。
*   **高低维互补 (Dimensional Hybridization)**：LLM 负责“高维语义推理”（发现为什么错、错得有多离谱），AST 负责“低维逻辑存真”（确定哪里确实缺了、哪里结构完全不符）。这种架构实现了**发散性寻找矛盾点、确定性闭环验证**的高阶教学能力。

## 2. 记忆层：BKT (Bayesian Knowledge Tracing) 隐状态追踪

### 2.1 数学背景：隐马尔可夫模型 (HMM) 与贝叶斯推断
BKT 将学生的知识点掌握程度视为一个不可见的隐藏状态（Hidden State），通过观测到的提交结果进行后验修正。

### 2.2 核心推导公式
对于任一知识点 $k$，维护其掌握概率 $P(L_t)$：

1.  **观测更新 (Posterior Update)**：
    *   若当前提交在知识点 $k$ 上表现**正确**：
        $$P(L_t \mid Correct) = \frac{P(L_{t-1}) \cdot (1 - P(S))}{P(L_{t-1}) \cdot (1 - P(S)) + (1 - P(L_{t-1})) \cdot P(G)}$$
    *   若当前提交在知识点 $k$ 上表现**错误**：
        $$P(L_t \mid Incorrect) = \frac{P(L_{t-1}) \cdot P(S)}{P(L_{t-1}) \cdot P(S) + (1 - P(L_{t-1})) \cdot (1 - P(G))}$$
    *(参数：$S$=失误率, $G$=猜测率)*

2.  **转场更新 (Transition/Learning)**：
    考虑练习过程中的习得效应 $P(T)$：
    $$P(L_{t+1}) = P(L_t \mid Obs) + (1 - P(L_t \mid Obs)) \cdot P(T)$$

## 3. 控制层：变分控制策略与严厉度系数 $\lambda_t$

### 3.1 数学背景：反馈控制系统与变分最优化思路
系统的目标是寻找一个动态平衡点：**最大化学习增益** vs **最小化认知负荷（疲劳与挫败感）**。我们引入控制器输出系数 $\lambda_t \in [0, 1]$。

### 3.2 严厉度泛函计算
定义认知负荷算子 $C(t)$，包含时间疲劳 $F_{time}$ 和连续失败挫折 $S_{fail}$：
$$C(t) = \omega_1 \cdot (1 - e^{-\rho \cdot t_{session}}) + \omega_2 \cdot \min(1, \frac{Failures}{N_{max}})$$

利用 Sigmoid 激活函数求解当前的严厉度系数：
$$\lambda_t = \text{Sigmoid} \left( \alpha \cdot \Delta L - \beta \cdot C(t) + \gamma \right)$$
*   **$\lambda_t \to 1$ (严厉模式)**：高挑战，AI 仅描述逻辑断层，强制采用苏格拉底式反问。
*   **$\lambda_t \to 0$ (扶持模式)**：高支架，AI 提供具体语法示例，进行“手把手”引导。

## 4. 行动层：基于 A* 启发式搜索的教辅动作选择

### 4.1 数学背景：启发式搜索 (Heuristic Search)
在确定了严厉度 $\lambda_t$ 后，系统需要从众多的错误点中搜索最值得提示的“目标行动”。

### 4.2 启发式评估函数 $f(n)$
定义状态选择的估价函数：
$$f(KP_i) = g(KP_i) + h(KP_i)$$
*   **$g(KP_i) = Severity_i$**：该错误的当前严重程度（实际代价）。
*   **$h(KP_i) = \frac{1}{P(L_t)_i}$**：根据 BKT 掌握度推算的预期引导代价（启发式项）。

**核心策略**：系统优先处理 $f(KP_i)$ 最大的节点。即：**优先提示那些学生掌握度极低且对当前 SQL 正确性影响最大的逻辑断层。**

## 5. 算法全串联：基于控制理论的闭环系统架构

系统运行的闭环逻辑流如下：

1.  **输入感知**：学生提交 $SQL_s$，**AST 算子**提取结构误差向量 $E_t$。
2.  **状态观测**：**BKT 模块**通过 $SQL_s$ 的正确性更新隐状态向量 $L_t$（知识点掌握度）。
3.  **策略决策**：**控制器**结合 $L_t - L_{t-1}$ 的增量（成长）与练习时长/连续失败次数（负荷），变分计算出本次引导的严厉度系数 $\lambda_t$。
4.  **行动搜索**：**A* 搜索算子**在 $E_t$ 的状态空间中，以 $L_t$ 为启发信息，搜索并锁定 1~2 个最优提示动作（Hint Actions）。
5.  **输出反馈**：将 $\lambda_t$（教学姿态）、**Hint Actions（作为核心逻辑约束）**、题目语境及学生 SQL 全量注入 LLM。LLM 在自由推理的同时，受 AST 硬性锚点的实时校准，生成既具启发性又具备极高逻辑确定性的自然语言反馈。
6.  **闭环回路**：学生根据反馈产生下一次提交，修正反馈回路，系统进入 $t+1$ 周期迭代。
