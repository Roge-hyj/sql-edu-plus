# SQL 智能教学系统 — 当前可执行算法与边界说明

本文档描述当前代码真正执行的 Phase 1～6 链路。历史版本中出现的“变分控制”“单一 λ”“伪 A*”和“LLM 自主诊断”不属于当前实现合同；版本化合同以 docs/27～29 为准。

## 1. Phase 1：有界判题

`core/parseval_data_generator.py` 在受控 schema、拓扑造数、沙盒执行和变异证据范围内比较标准 SQL 与学生 SQL。它输出权威的 `CORRECT`、`WRONG` 或 `UNDECIDED` 判定及其证据状态。

Phase 2 不能改写这个判定；`UNDECIDED`、平台错误、安全拦截和语法错误不会产生语义学习观测。

## 2. Phase 2：结构化因果诊断

`core/error_diagnosis.py` 只消费 Phase 1 的有界对象和内部结构差异。20 个冻结 `rule_id` 由规则目录约束，输出 `phase2.public.v1`。诊断包中的：

- `evidence_grade` 是当前 candidate bundle 的最高证据等级；
- `knowledge_points` 是 bundle 内 diff 的展示并集；
- `verified_diff_ids` 与 `unverified_diff_ids` 是每个 diff 的证据分区。

因此，Phase 3 不把 candidate 的知识点并集当作掌握事实，只使用 `phase3.rule_skill_map.v1` 将一个强证据 `rule_id` 映射为一个原子技能。

## 3. Phase 3：可信观测、调度与 BKT

正确提交只有在服务端 Question–Skill Q-matrix 存在以下行时，才产生正观测：

```text
role = PRIMARY
observable_on_correct = true
provenance ∈ {AUTHOR_DECLARED, GENERATED}
```

`INFERRED` 只能作为设计元数据，不能单独证明一次正确掌握。没有 Q-matrix 时，判题仍然返回正确结果，但学习状态为 `SKIP_NO_ASSESSMENT_MAP`。

错误提交只接受 Phase 2 的 `SUPPORTED`、强证据 candidate，经 `rule_id → atomic skill` 映射后进入 BKT；弱证据、suppressed、unresolved 和版本/阶段不一致的 candidate 一律跳过。

### 3.1 受约束目标排序

实现类名是 `ConstrainedPriorityScheduler`，不是 A*：系统没有状态图、路径代价或启发式搜索。候选先按硬层级排序：

1. `FDP/PRIMARY`；
2. `SECONDARY`，且受支架预算限制最多选择一个。

suppressed/unresolved 永不选择，候选分数不能让 secondary 越过 primary。层内使用独立的版本化分数：

```text
priority_score =
    0.30 * instructional_impact
  + 0.25 * recurrence
  + 0.20 * mastery_deficit
  + 0.15 * question_alignment
  + 0.10 * evidence_strength
```

当前策略和参数均标记为 `UNCALIBRATED_MVP`。

### 3.2 支架与下一题难度分轴

当前任务的支架需求使用可解释的行为代理，不声称测量疲劳或真实认知负荷：

```text
support_need = clamp(
    0.35 * (1 - mastery)
  + 0.30 * failure_streak_norm
  + 0.10 * recent_hint_ratio
  + 0.10 * behavioral_support_need
  - 0.15 * recent_unassisted_success,
  0, 1)
```

它映射到四档 `[0, .25) → L1`、`[.25, .50) → L2`、`[.50, .75) → L3`、`[.75, 1] → L4`。下一题难度单独使用：

```text
challenge_index = clamp(
    0.50 * mastery
  + 0.30 * recent_unassisted_success
  + 0.20 * (1 - behavioral_support_need),
  0, 1)
```

`challenge_index` 不参与当前错误排序，也不决定当前提示深度；`challenge_readiness` 只是兼容别名。上述指标不是 sigmoid 或变分解析解，待离线校准后才可换版本。

行为代理只读取当前活动窗口的可信语义观测；30 分钟以上空闲会话重置。语法、平台、安全和 `UNDECIDED` 事件不进入语义失败比例，语法只保留独立计数；一次正确只结束连续失败，不删除窗口内较早的失败。

### 3.3 标准四参数 BKT

当前参数为 `P(L0)=0.20`、`slip=0.10`、`guess=0.20`、`transition=0.10`，版本为 `phase3.bkt_parameters.v1`。对于 prior `p`：

```text
correct posterior = p*(1-slip) / (p*(1-slip) + (1-p)*guess)
incorrect posterior = p*slip / (p*slip + (1-p)*(1-guess))
next_prior = posterior + (1-posterior)*transition
```

持久化保存 raw `posterior_mastery` 和 `next_prior`。如果界面需要 EMA，使用独立展示函数，不能覆盖 BKT 状态或作为下一次 prior；不再追加固定的 `0.6*old + 0.4*new`。

## 4. 端到端闭环

```text
学生提交
  → Phase 1 权威有界判定
  → Phase 2 20-rule 诊断与证据分区
  → Q-matrix / rule-to-atomic-skill 可信观测门控
  → ConstrainedPriorityScheduler + support_need
  → raw BKT 状态与事件幂等落库
  → Phase 4/5 单目标确定性反馈
  → submission、教学审计、聊天和 response snapshot 事务提交
```

学生只能看到正误、最终反馈和不含技能身份的学习摘要。完整诊断包、candidate/rule/skill、Q-matrix、witness、AST/reference SQL 和内部 provenance 仅留在服务端审计边界内。
