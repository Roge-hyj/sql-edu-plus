## 2. 总体结论

本项目是一个由三部分组成的混合系统：

1. SQL 在线教学产品：账号、题目、SQL 提交、判题、经验等级、聊天和教师题库管理。
2. SQL 语义判题研究内核：SQL 安全检查、`sqlglot` AST/结构 IR、动态反例造数、沙盒执行、变异测试和错误归因。

当前最成熟的是后端判题研究内核和配套实验资产；产品前端目前只是 uni-app 工程骨架与接口封装，登录、学生练习和教师管理页面已经不存在，因此项目当前不能作为完整教学产品直接运行。

文档描述的 BKT 能力追踪、动态教学控制系数 `lambda_t` 和行动搜索闭环，目前没有对应的完整实现。现有后端主要落地了 Phase 1 Observe/感知阶段：判题、结构差异分析、测试数据生成和错误归因。

### 4.3 实际判题流程

`/ai/check-sql` 当前的主要执行链：

1. JWT 鉴权并读取题目。
2. 关键字级安全检查，只允许查询语句。
3. 使用 `sqlglot` 解析学生 SQL。
4. 将题目的 `schema_preview` 转换为判题 Schema。
5. 对标准 SQL 和学生 SQL 构建结构 IR/AST Diff。
6. 根据差异生成边界、NULL、连接、聚合、分组、排序等测试数据。
7. 在 SQLite 兼容层或配置的原生 MySQL 执行。
8. 比较标准答案和学生答案的行、列、顺序及结果。
9. 执行部分变异替换并收集证据。
10. 将 AST、数据和变异证据归因到知识点。
11. 保存提交和聊天消息，正确提交时计算经验值。

### 7.3 2026-08-12 14:53:50（北京时间，UTC+8）Phase 1 反例穿透专项修复

本轮按用户指定范围修复 WHERE 逻辑优先级与括号边界、深层子查询、窗口函数、CTE/递归 CTE 以及“策略已激活但没有可观察反例”。别名导致的重复列名和歧义列按用户要求冻结，本轮未修改相关逻辑。

实现调整：

- 对嵌套 `IN (SELECT ...)` 按每个 `SELECT` 作用域解析物理表和列，从最深层反向建立连续值域路径；标准/学生叶子谓词各保留一条可达路径，避免多层结果同时为空。
- 对同表相关 `AVG/MIN/MAX` 子查询生成重复关联键分组与边界值；补充 `gpa`、`grade`、`purch_amt`、`revenue`、`totalitems` 等数值列启发，避免 SQLite 文本类型比较遮蔽聚合边界。
- WHERE 布尔树在叶子集合相同但括号/优先级不同时，枚举有限真值向量，选取两棵树结果不同的赋值并回写到测试行；支持数值比较和 `LIKE` 叶子。
- 窗口分区列不再被“主键候选去重”恢复为唯一值，保留多分区、分区内并列键，稳定区分 `RANK/ROW_NUMBER` 和移除 `PARTITION BY` 的差异。
- 递归层级数据增加不可达孤立节点，区分递归遍历与直接读全表；递归 CTE body 变化增加专项替换变异；对真正能产生重复状态的 `UNION ALL/UNION` 层级查询保留重复递归状态。
- 评测语料中 `value = MAX(group)` 与 `value >= MAX(group)` 被修正为等价样本；任何合法数据都无法让当前行大于所属组的最大值，因此不伪造反例。

## 8. 主要风险清单

### 严重

1. 公共题目响应包含 `correct_sql`，匿名列表/详情会泄露标准答案。
2. 前端页面全部缺失，产品无法完成基本用户流程。

### 高

1. Alembic 有两个 head，迁移不能按单一 head 部署。
2. `sqlglot` 被核心代码直接使用，但未写入 `requirements.txt`。
3. 教师邀请码硬编码为 `ILOVESQL`。
4. `/mail/test` 和验证码发送缺少认证、限流和防滥用措施。
5. CORS 实际为全开放来源并允许凭证。
6. 判题在异步 API 中同步执行计算密集型任务，可能阻塞事件循环。
7. 原生 MySQL 判题需要较高数据库权限，隔离和最小权限要求未被产品化保证。
8. 题目响应组装没有完整返回 `sql_dialect` 和 `engine_version`。

### 中

1. 用户名没有数据库唯一约束，但业务层按唯一值使用。
2. SQLite 未明确启用外键，级联删除行为可能与 MySQL 不一致。
3. 聊天记录按时间升序再截断，消息多时可能返回最老记录而不是最近上下文。
4. 生产 SQLAlchemy 引擎固定 `echo=True`，可能记录敏感 SQL 和参数。
5. 前端没有请求超时和并发 Token 刷新协调。
6. 前端默认一次请求最多 1,000 道题，缺少真正的增量分页体验。
7. 前端接口类型落后于后端响应。

## 9. 建议处理顺序

1. 先拆分学生/教师响应模型，确保任何学生接口都不返回 `correct_sql`。
2. 恢复最小可用前端：登录、题目列表、题面、SQL 输入、提交反馈。
3. 修复前端依赖和构建入口，补齐类型检查。
4. 合并 Alembic 两条迁移分支，验证全新数据库升级流程。
5. 将 `sqlglot`、可能的 `pypdf` 等实际运行依赖写入依赖清单。
6. 移除硬编码邀请码，增加邮件接口限流、验证码过期和重放保护。
7. 按环境限制 CORS、关闭生产 SQL 回显、恢复邮件证书校验。
8. 将判题任务移出 FastAPI 事件循环，并限制沙盒资源。
9. 在基础产品链路稳定后，再实现真正的 BKT、`lambda_t` 和自适应教学行动选择。
