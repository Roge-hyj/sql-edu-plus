# SQL 智能教学系统 — 具体化闭环控制流图

本文档记录了系统核心闭环流程的数据流图（Mermaid 格式）及各阶段的详细数据输入、处理工具/公式与输出规范，以便开发联调与后续实验比对。

### 图例说明 (Legend)

- **I (Input)**: 输入数据结构 / 变量。
- **T (Tool / Technology / Formula)**: 中间处理工具、执行代码模块、核心算法或数学公式。
- **O (Output)**: 输出数据结构 / 结果变量。

## 二、 核心环节数据流细化规范

### 入口：学生提交动作 (U $\rightarrow$ API)

- **输入（Input）**：
  - `student_sql` (str): 学生在前端编辑框里写的 SQL 代码字符串。
  - `question_id` (int): 题目唯一标识符。
  - `language` (str): 语言标识（"zh-CN" / "en" / "zh-TW"）。
- **处理工具（Tool）**：FastAPI APIRouter（`sql-edu-backend/routers/ai.py` 中的 `@router.post("/check-sql")`），通过 `QuestionRepository` 从 MySQL 数据库中查出该题目的标题与内容 `question_content`、标准答案 `correct_sql`、表结构预览 `schema_preview` 及列名约束 `required_output_columns`。
- **输出（Output）**：
  - 打包好的判题元数据与题目详情：`(student_sql, correct_sql, schema_preview, required_output_columns, question_content)`。

---

### 步骤 1：判题环境准备 (API $\rightarrow$ SETUP)
*   **输入（Input）**：
    *   `schema_preview` (str | None): 题目的 DDL 紧凑表示（如 `classroom(building, room_number, capacity);`）。
*   **处理工具（Tool）**：`core/judge_setup.py`。
    *   通过 `generate_init_sql_from_schema_preview` 函数将紧凑表结构解析并映射为内存沙盒的标准 SQL DDL。
    *   通过 `execute_setup_sql` 在当前会话连接中完成建表操作（在此环节通常只初始化空的表结构）。
*   **输出（Output）**：
    *   一个被隔离且已经创建好临时表结构的活跃沙盒数据库连接。

---

### 步骤 2：阶段 1 Observe (SETUP $\rightarrow$ S1 OBS)
*   **输入（Input）**：
    *   `student_sql` (str), `correct_sql` (str)。
    *   前置步骤准备好的沙盒数据库连接。
*   **处理工具（Tool）**：`core/sql_judge.py` 中的 `SQLJudgeService.judge_sql_detailed`。
    *   对学生 SQL 做安全性正则检查 `_check_sql_safety`，拦截高危词（DROP/DELETE 等）。
    *   利用 `parseval_data_generator.py`（ParSEval 计划感知造数模块），提取标准 SQL 中的谓词与 Join 键，利用符号执行和分支覆盖算法，针对两边 SQL 的逻辑执行分支**动态生成特定测试样例数据**。
    *   在沙盒中导入该测试数据，并分别执行学生 SQL 与标准 SQL，对比各自结果集。
*   **输出（Output）**：
    *   `is_correct` (bool): 两者在动态生成的特定测试数据上是否完全等价。
    *   `error_message` (str | None): 编译错误、执行报错或行数/数据不匹配的文本说明。
    *   `student_result_meta` 和 `correct_result_meta` (dict): 两边在测试数据上运行结果集的行数、列数、列名列表及前 3 行样本数据 `sample_rows`（用作后续 `E_data` 传感器和 AI 数据反例引导）。

---

### 步骤 3：多源传感器并行诊断与打包 (S1 OBS $\rightarrow$ S1 各传感器 $\rightarrow$ E_LLM)

系统分三个正交维度进行数据提纯：

1. **E_AST (结构传感器)**
  - **输入**：`student_sql`, `correct_sql`。
  - **工具**：`core/ast_analyzer.py` 内的 `sqlglot` 解析器。
  - **输出**：包含缺失子句、冗余算子、AST 节点差异的列表。
2. **E_data (执行数据传感器)**
  - **输入**：`student_result_meta`, `correct_result_meta`, `error_message`。
  - **工具**：`core/error_attribution.py` 的 `_judge_features`。
  - **输出**：提取出的列数不一致、重复行数异常、空值匹配失败等执行特征。
3. **E_MUT (变分隔离传感器/Mutation Testing)**
  - **输入**：`student_sql` 与 `correct_sql` 的 AST 树。
  - **工具**：`core/parseval_data_generator.py` 内的 `_run_mutation_tests`。它把学生 SQL 的某一部分（如 WHERE 条件）强行替换为标答对应部分，然后在沙盒中复测。
  - **输出**：哪一部分被替换后运行正确，提供该子句对错的“强物理隔离证据”。
4. **E_LLM (综合证据打包器)**
  - **输入**：上述三路传感器的原始诊断结果。
  - **工具**：`core/error_attribution.py`。
  - **输出**：`llm_arbitration_input` (JSON 字典)，里面打包了双向 KP 比对和所有的物理、执行、变分证据。

---

### 步骤 4：阶段 2 Diagnosis (E_LLM $\rightarrow$ S2 DIA)

- **输入（Input）**：
  - `llm_arbitration_input` 证据包。
- **处理工具（Tool）**：`core/error_diagnosis.py`。
  - **离线/确定性路径**：`diagnose_record` 启发式规则融合算法，以 `PEDAGOGICAL_PRIORITY`（教学优先级权重）和证据源的可靠度（E_AST 为 1.0, E_MUT 为 0.9, E_data 为 0.78）为权重进行优先级排序。
  - **在线/大模型路径**：`diagnose_record_with_llm`，调用 LLM 根据证据包做双向比对并判定错误类型为（Lacking、Confusion、Logical、Generality、Complication）之一。
- **输出（Output）**：
  - `attributions` (List[KPAttribution] / List[ASTError]): 最终知识点级错因归因集合。每个归因包含：`knowledge_point_id`（如 `group-by`）、`l2_code`（如 `GB_SIMPLE`）、`severity`（严重度权重）、`detail`（详细错误原因）。

### 步骤 5：阶段 3 Reasoning & Control (S2 KP $\rightarrow$ S3)

此阶段完成贝叶斯画像更新与控制系数变分求解：

1. **有效误差向量构建 ($E_t^*$)**
  - **输入**：`attributions` 中诊断出的缺陷，以及大模型判题对错 `is_correct`。
  - **工具**：`core/bkt_service.py` -> `update_mastery_from_errors`。
  - **更新过滤机制（True/False/Skip分流）**：
    * **若整体正确 (`is_correct == True`)**：本题考查的所有知识点均被标记为 `observed_correct = True`（等价写法噪声过滤）。
    * **若整体错误 (`is_correct == False`)**：被明确归因有错的知识点标记为 `observed_correct = False`（有效误差提取），而考查了但未被标记有错的知识点**直接保持不变（Skip，不参与 BKT 迭代更新）**。
  - **输出**：精准误差向量 $E_t^*$。

2. **BKT 记忆追踪更新与惯性平滑**
  - **输入**：$E_t^*$、上一步查出的学生在 `knowledge_mastery` 数据库中记录的先验掌握度向量 $P(L_{t-1})$。
  - **工具/公式**：贝叶斯 BKT 递推数学公式与一阶低通惯性滤波器：
    - **后验概率计算**（设 $P(Slip)=0.1, P(Guess)=0.2$）：
      * 若 `observed_correct = True`：
        $$P(L_t \mid Correct) = \frac{P(L_{t-1}) \cdot (1 - P(Slip))}{P(L_{t-1}) \cdot (1 - P(Slip)) + (1 - P(L_{t-1})) \cdot P(Guess)}$$
      * 若 `observed_correct = False`：
        $$P(L_t \mid Incorrect) = \frac{P(L_{t-1}) \cdot P(Slip)}{P(L_{t-1}) \cdot P(Slip) + (1 - P(L_{t-1})) \cdot (1 - P(Guess))}$$
    - **过渡学习推导**（设 $P(Transition)=0.1$）：
      $$P(L_{\text{new\_raw}}) = P(L_t \mid Obs) + (1 - P(L_t \mid Obs)) \cdot P(Transition)$$
    - **低通滤波器平滑处理**（设惯性平滑因子为 0.6，防止单次失误/猜测导致概率急剧抖动）：
      $$P(L_{t+1}) = 0.6 \cdot P(L_{t-1}) + 0.4 \cdot P(L_{\text{new\_raw}})$$
  - **输出**：学生最新的后验知识掌握概率映射表 `current_mastery_state`。

3. **认知负荷计算 $C(t)$**
  - **输入**：系统提取最近 60 分钟内提交的 `timestamps`；以及当前题目的连续失败次数 `consecutive_failures`。
  - **工具/公式**：
    * **疲劳度**（设会话衰减率 $\rho = 0.05$，$t_{session}$ 为会话持续分钟数）：
      $$Fatigue = 1 - e^{-0.05 \cdot t_{session}}$$
    * **挫败度**：
      $$Frustration = \begin{cases} \min(1.0, \frac{\text{Failures}}{5}) & \text{if } is\_correct = False \\ 0.0 & \text{if } is\_correct = True \end{cases}$$
    * **综合负荷**：
      $$C(t) = 0.5 \cdot Fatigue + 0.5 \cdot Frustration$$
  - **输出**：系统认知负荷标量 $C(t) \in [0, 1]$。

4. **控制律 $\lambda_t$ 计算**
  - **输入**：`current_mastery_state`、`previous_mastery_state`、$C(t)$。
  - **工具/公式**：
    * 计算学习成长率（仅针对本题实际考核/涉及的知识点集合 $KP_{\text{involved}}$）：
      $$\Delta L = \frac{1}{|KP_{\text{involved}}|} \sum_{k \in KP_{\text{involved}}} (P(L_{t,k}) - P(L_{t-1,k}))$$
    * 求解控制系数（基于变分法稳态解析解，使用 Sigmoid 激活函数，设定权重 $\alpha=0.6, \beta=0.4$，偏置 $\gamma=0.5$）：
      $$\lambda_t = \text{Sigmoid}(\alpha \cdot \Delta L - \beta \cdot C(t) + \gamma) \quad (\text{Clamped to } [0.05, 0.95])$$
  - **输出**：连续控制系数 $\lambda_t$。

5. **A* Heuristic Search 优先级排序**
  - **输入**：$E_t^*$，`current_mastery_state`，$\lambda_t$。
  - **工具/公式**：
    * A* 启发式搜索评估函数（基于控制系数 $\lambda_t$ 比例进行凸组合双向自适应调优）：
      $$\text{challenge\_term} = Severity_i + (1 - P(L_t)_i)$$
      $$\text{scaffolding\_term} = (1 - Severity_i) + P(L_t)_i$$
      $$Priority(KP_i) = \lambda_t \cdot \text{challenge\_term} + (1 - \lambda_t) \cdot \text{scaffolding\_term}$$
  - **输出**：被截断排序后的核心错误列表（最大提示数设为 2，防止认知过载）。

### 步骤 6：阶段 4 TeachingAction (S3 $\rightarrow$ S4 ACT)

- **输入（Input）**：
  - A* 搜索确定的 L2 错误点；控制系数 $\lambda_t$；学生在这些错误点上的具体掌握度 $P(L_t)_i$。
- **处理工具（Tool）**：`core/action_selector.py` 内的 `ActionSelector.select_hint_actions`。
  - 调用阶梯降噪逻辑 `build_hint_action` 确定当前错误的引导深度 `depth`：
    - 若 $\lambda_t > 0.7$ (学生状态好)，设置为 **Depth 1** (高挑战，仅讲逻辑，不提关键字)。
    - 若 $\lambda_t \in [0.5, 0.7]$，根据该项掌握度是否熟悉决定，熟悉则挑战，不熟悉则退为 **Depth 2**。
    - 若 $\lambda_t \in [0.3, 0.5]$，掌握度低时给 **Depth 3** (保姆引导，举通用例子)，否则 Depth 2。
    - 若 $\lambda_t < 0.3$ (精疲力竭/挫败高)，强制给 **Depth 3**。
- **输出（Output）**：
  - `hint_actions` (List[HintAction])，包含各自原子提示描述（`prompt_fragment`）。
