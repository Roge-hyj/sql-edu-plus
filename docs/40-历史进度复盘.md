| 双侧作用域配对 | 只有 AST 结构路径与 scope kind 同时一致时，才给标准/学生 scope 绑定同一个 `conceptual_scope_id`                                     | 无可靠配对时保留 `PARTIAL/unscoped`，不凭同名表、列或别名猜测                           |

关系边的实际生成规则是：普通表达式子查询输出 `PARENT + SUBQUERY_OF`；FROM/JOIN 派生表输出 `PARENT + DERIVED_FEEDS`；LATERAL 派生表在此基础上增加 `LATERAL_TO`；只有能够从限定列引用证明其读取外层 query block 时才增加 `CORRELATED_TO`。因此 `LATERAL_TO` 表示语法上的 LATERAL 求值关系，`CORRELATED_TO` 表示已经发现真实外层引用，两者不混为一类。

### 3.2 Phase2：错因诊断、路径 bundling 与认知归因

#### 3.2.1 Phase2 是否识别等价性

Phase2 **不独立判定 SQL 等价**。它只消费 Phase1 的权威 rich verdict：


| Phase1 状态                                          | Phase2 行为                               | 是否允许认知归因/学习更新                |
| -------------------------------------------------- | --------------------------------------- | ---------------------------- |
| `SUPPORTED + NOT_EQUIVALENT + WRONG`               | 进入 20-rule 诊断、因果 bundling 和 witness/QSS | 只有强证据候选可以继续                  |
| `SUPPORTED + NO_COUNTEREXAMPLE_FOUND + CORRECT`    | 生成 operationally accepted 正确包           | 只有权威 Q-matrix 可产生正观测；不宣称全局等价 |
| `UNDECIDED`                                        | 返回未决，不写“你错在……”                          | 否                            |
| `ENGINE_GAP/INPUT_GAP/KNOWN_GAP/SEMANTIC_BOUNDARY` | 返回平台或能力边界                               | 否                            |
| syntax/safety                                      | 专用出口                                    | 不进入语义规则和 BKT                 |




#### 3.2.2 作用域与“沿路径划分错误点”的真实能力

系统先构建 `ScopedQueryGraph`，而不是把整条 SQL 压成一条平坦链。它保留 ROOT、CTE、DERIVED、SUBQUERY、SET/SET_BRANCH 等 scope，以及 `CTE_FEEDS`、`SUBQUERY_OF`、`CORRELATED_TO`、`SET_MEMBER_OF`、`LATERAL_TO` 等 composition edge。每个可配对 scope 内再按 14 个逻辑阶段排序：

```text
PRECHECK → CTE_PRODUCER → SOURCE_JOIN → ROW_FILTER → GROUP_AGG
→ GROUP_FILTER → WINDOW → QUALIFY → PROJECTION → DISTINCT
→ SET_OP → ROOT_ORDER → PAGINATION → EXTENSION
```

对学生展示时折叠为 S1 来源/连接、S2 行过滤、S3 分组粒度、S4 组过滤、S5 计算/投影/集合、S6 排序/截断。每个 diff 同时保存 scope、logical stage、teaching stage、`diff_id/obligation_id/mutation_test_id`，因此能形成“哪个 query block 的哪个逻辑阶段发生了什么差异”的有序集合。作用域无法可靠配对时，系统保留 unscoped/partial，而不是错绑到 root。

这里的边不是只在 `ScopedQueryGraph` 枚举中声明：Phase1 `_build_phase1_scope_metadata` 已从真实 AST 自动生成它们，下游再做 allowlist、端点、类型和完整性校验。自动化链路覆盖普通子查询与 LATERAL 的 `generate_and_compare → scope_metadata → ScopedQueryGraph`，两者均为 `COMPLETE`；Docker PostgreSQL 16 原生执行也分别得到 `SUBQUERY_OF`，以及 `DERIVED_FEEDS + LATERAL_TO + CORRELATED_TO`。

#### 3.2.4 Fault bundling、错误集合和最早偏离点

真实算法分两趟：

1. 扫描所有 scope 和所有阶段，生成候选；不会因为 S1 命中就停止，因此独立的 S6 错误仍可保留。
2. 按 `(scope_id, rule_id)` 聚合共享 diff/obligation 的候选。
3. 只接受有 stable evidence 绑定的 `CAUSES/MASKS/RELOCATES_TO` 做抑制；`CO_OCCURS` 只能表示共现，不能制造因果。
4. 输出四个集合：`primary_fdp`、`secondary_roots`、`suppressed_symptoms`、`unresolved_candidates`。
5. 在 blocking causal roots 中，按 scope 顺序、逻辑阶段、证据等级、修复性、严重度和稳定 ID 选 `primary_fdp`。

所以系统当前能找到的是：**在已配对 query scope 和已验证因果根集合中的“首要教学偏离点”**。它不是数据库执行引擎的通用 tuple provenance，也不能在 scope partial、无 witness、只有 AST 差异或多个错误互相遮蔽时证明“语义上绝对最早”的错误；这类候选会进入 secondary 或 unresolved，而不会强行排序成唯一根因。

#### 3.2.5 当前“认知归因”能做到和不能做到的事


| 能做到                                                                     | 不能做到                                                                                  |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 把强证据错误映射到 20 个原子 SQL skill，例如 `S2_NULL_LOGIC → null.three_valued_logic` | 不能仅凭一次 SQL 判断学生是“不知道、概念混淆、粗心还是抄写失误”                                                   |
| 用 QSS 输出“当前行为—冲突/物证—苏格拉底式问题”                                            | 不能把模板式解释等同于经过教育实验验证的认知模型                                                              |
| 区分 primary、独立 secondary、dependent symptom、unresolved                    | 不能把阶段先后或 AST 距离当成心理因果                                                                 |
| 对高级差异保留 `UNCLASSIFIED_SUPPORTED_DIFF` 和证据，不错误套用最近的规则                    | 当前 20 条之外的 window frame、复杂 CTE/集合、alias/function/dialect 等没有完整 misconception taxonomy |




### 3.3 Phase3：可信学习更新与教学支架选择



#### 3.3.1 什么信息会更新，什么信息不会更新

每个学习事件保存：`taxonomy_version`、`skill_id`、正/负结果、来源与版本、evidence grade、Phase2 candidate/rule、source role、logical stage、实际支架等级，以及 BKT 更新前后的数值。状态以 `(user_id, taxonomy_version, skill_id)` 分区，避免 broad curriculum skill 与 atomic skill 共用一个概率。

#### 3.3.2 BKT 当前具体更新什么

当前使用未校准四参数 BKT：`P(L0)=0.20`、`slip=0.10`、`guess=0.20`、`transition=0.10`。每次观测先保存 Bayes 后验 `posterior_mastery`，再保存学习转移后的 `next_prior`；下一次只读取 `next_prior`。状态还保存 observation count、参数版本和 state version；唯一键 `(submission_id, taxonomy_version, skill_id)` 防止重放重复更新。UI EMA 与 BKT 状态分离，不会二次平滑后再写回。

这证明的是“公式、来源和幂等闭环已经接通”，不是参数有效。当前仍为 `UNCALIBRATED_MVP`，没有真实学生轨迹支持 slip/guess/transition、支架权重或 mastery 阈值的教育学解释。

#### 3.3.3 如何选择本轮教学目标和支架深度


| 决策       | 当前已实现策略                                                                                                                                                      | 当前欠缺                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 选哪个错误先教  | `FDP/PRIMARY` 是不可被分数越过的硬层级；其后最多加入一个 independent secondary；suppressed/unresolved 永不选                                                                          | priority 权重是工程初值，尚未用学习收益校准；Phase4 实际每轮仍只展示一个 selected target                          |
| 同层候选排序   | `0.30*instructional_impact + 0.25*recurrence + 0.20*mastery_deficit + 0.15*question_alignment + 0.10*evidence_strength`                                      | `instructional_impact` 和各权重不是心理测量结果                                                   |
| 本次提示深度   | `support_need = 0.35*(1-mastery) + 0.30*failure_streak + 0.10*recent_hint_ratio + 0.10*behavioral_support_need - 0.15*recent_unassisted_success`，裁剪到 `[0,1]` | 提交前提示暴露尚未完整记录，所以 `recent_unassisted_success` 当前保守为 0；behavioral need 只是事件代理，不是疲劳/认知负荷 |
| L1–L4 划分 | `[0,.25)→L1`、`[.25,.50)→L2`、`[.50,.75)→L3`、`[.75,1]→L4`                                                                                                      | 阈值未校准；当前只能说四档在路由中可达，不能说是最优剂量                                                          |
| 下一题难度    | `challenge_index` 单独由 mastery、无辅助成功和行为支持代理计算，只用于下一题                                                                                                          | 当前没有完整的自动选题器和经验证难度模型；不得拿它决定当前 hint 深度                                                 |


连续相同可信错误的现有工程行为可从 L2 提升到 L3、L4，推荐等级、实际等级、BKT 事件和教学审计会保持一致。但 broad↔atomic skill 桥接、题目 revision fingerprint、真实行为校准和跨课程迁移仍未完成。

### 3.4 Phase4：把选中的错因落实为教学支架

Phase4 不重新判题、不重排错误、不读取标准 SQL。它只消费 Phase3 已绑定的一个 `selected_target`，并核对 `candidate_id/rule_id/skill_id/taxonomy/stage/source role/evidence grade` provenance 后生成动作。


| 支架等级 | 当前实际交付内容                                | 教学意图               | 真实边界                                     |
| ---- | --------------------------------------- | ------------------ | ---------------------------------------- |
| L1   | 一个与首要错因绑定的苏格拉底式自查问题                     | 促使学生先自行检查概念        | 没有可信 target 时只能给通用流程问题，不是假装个性化           |
| L2   | “当前查询行为” + 自查问题                         | 让学生先理解自己的 SQL 做了什么 | 不提供物证或修复方向                               |
| L3   | 当前行为 + 最小冲突/物证 + 自查问题                   | 用真实反例打破错误心智模型      | witness 不可安全绑定时必须降级，不能编造数据               |
| L4   | 当前行为 + 物证 + rule-specific 概念检查方向 + 自查问题 | 给出解决原则，但仍让学生完成 SQL | 20 条规则有版本化 reflection；只给概念检查步骤，不生成完整 SQL |


当前能称为“使用正确支架”的含义是：支架与已验证 rule、选中 target 和推荐深度一致，并且只展示一个焦点错误。它还没有通过真实学生实验证明“这个支架一定最有效”，也没有实现学生回答苏格拉底问题后的多轮理解判断、按回答动态换支架、自动生成相似练习或教师人工干预策略。

正确提交、syntax、安全拦截和无可信 target 不伪造自适应教学；Phase4/5 任一步失败都保留权威 verdict，并 fail-closed 到可审计 L1。

### 3.5 Phase5：启发性自然语言与答案防泄漏



#### 3.5.1 当前真实语言能力


| 能力     | 当前实现                                                                                                                 | 不能扩大声称的部分                                                            |
| ------ | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 自然语言反馈 | `zh-CN/zh-TW/en` 三种确定性模板；按“当前行为、冲突与物证、修改前检查方向、请思考”分段；L2-L4 可由 LLM 对已批准片段做一对一润色                                       | 语言质量、语气适配和长对话连贯性尚未通过真实教师/学生盲评；L1、正确接受、安全/语法通知仍固定本地模板                 |
| 教导与启发  | 20 条规则各有概念级 reflection 和苏格拉底式问题；不直接给替换 SQL                                                                           | 这是教学设计上的“启发式结构”，尚无教师评分、学生理解度、学习增益或 A/B 证据证明其启发效果                     |
| 个性化    | 根据选中错因、mastery/failure/hint history 调整 L1–L4 深度                                                                      | 除目标和深度外，尚未根据语言水平、常见误解类型、阅读能力或历史自然语言回答改写内容                            |

#### 3.5.2 当前防泄漏机制

1. Phase5 的 LLM 只接收 Phase4 已批准的 action 文本、动作类型、语言和实际等级；不读取 `correct_sql`、标准 AST、mutation SQL 或完整 witness database。固定动作（问题、接受、安全/语法通知）不能被模型改写。
2. 新提交学生响应中的完整 `diagnostic_package` 固定为 `null`，避免 L1/L2 绕过裁剪直接看到 primary/secondary/witness/QSS。
3. 公共诊断包递归拒绝 `answer_sql/correct_sql/standard_sql/reference_sql/replacement_sql/mutation_sql/test_database/raw_observation` 等字段。
4. 最终反馈对标准 SQL 全文和 `SELECT/WHERE/GROUP BY/HAVING/ORDER BY/LIMIT/OFFSET` 等抽取片段做归一化泄漏扫描；命中则拒绝。
5. LLM 超时、provider 错误、JSON 结构错误、动作错配、语义锚定不足或泄漏校验失败时，先回退 deterministic safe renderer；主渲染/最终安全校验本身失败时，再使用独立本地 emergency renderer 降为不含答案的 L1，并记录 `OVERRIDDEN/FALLBACK`；BKT 只记录实际交付等级。
6. 学生可见 `teaching_support` 只含推荐/实际等级和策略版本，不含 rule、skill、candidate、observation、Q-matrix 或 witness。

因此当前有真实证据支持的是“在现有确定性模板、LLM 输出门禁和已覆盖攻击形状下不泄漏”：PG 原生 16 个路由分支和 MySQL 原生 14 个路由分支的 learner-safe rate 均为 1.0；LLM 具体生成质量目前只有 mock contract，尚无在线 provider 质量结论。它还不是形式化 non-interference 证明；标准答案的同义改写、编码/Unicode 混淆、模型间接提示、客户端旁路字段和红队攻击仍需单独的 adversarial leakage suite 与人工审查。
