# 多 Witness 造数策略整合重构计划

日期：2026-08-16
状态：执行中
适用范围：Phase 1 SQL 结构分析、测试数据生成、测试变异、错误归因完整链路

## 1. 背景与现状

当前核心造数器 `sql-edu-backend/core/parseval_data_generator.py` 包含 59 个
`_apply_*` / `_add_*` 探针函数和 7 个注册式策略。现有实现主要采用以下模式：

```text
生成一份基础数据库
→ 按固定顺序调用大量探针
→ 每个探针直接改写行和列
→ 使用最终数据库执行标准 SQL 与学生 SQL
```

该模式已经覆盖大量教学场景，但存在结构性问题：

- 后执行探针可能覆盖前一探针制造的反例；
- JOIN、HAVING、DISTINCT、窗口、CTE 等策略可能竞争同一单元格；
- 注册式策略与固定调用存在重复执行；
- 策略主要报告“已激活”，不能证明约束最终仍然存在；
- 一份数据库被迫同时满足所有差异，导致策略组合复杂度迅速上升；
- Schema 不可信时，后续造数结果没有意义；
- 无法精确回答“哪个结构差异由哪个数据世界区分”；
- 执行失败、方言能力边界和真正造数失败尚未完全分层。

本计划不继续堆叠新的 `_apply_*` 函数，而是将系统重构为：

```text
AST 差异
→ 语义区分义务
→ 策略规划与冲突分析
→ 生成多个兼容的小型反例数据库
→ 实际执行验证
→ 失败后定向补数
```

## 2. 核心正确性模型

对于预期不等价的标准 SQL `Q_standard` 和学生 SQL `Q_student`，只需找到至少一个
有限数据库 `D` 满足：

```text
Q_standard(D) != Q_student(D)
```

即可得到经验反例。因此系统不再要求一份数据库承载全部探针，而是允许生成多个
相互隔离的 `WitnessWorld`：

```text
World 1：突出 LEFT JOIN 悬空元组
World 2：突出 HAVING 临界分组
World 3：突出 ORDER BY 方向和并列值
```

对于不等价判断，只要任意一个 world 成功区分即可。对于等价判断，有限测试只能提供
经验支持，不能宣称对任意 SQL 和任意数据库的形式化完备性证明。

## 3. 总体目标

1. 建立可信 Schema、查询块和名称作用域模型。
2. 将 AST 差异编译为可验证的语义区分义务。
3. 将策略由“直接改行”迁移为“声明约束”。
4. 建立单元格所有权、锁、优先级和冲突检测。
5. 由 planner 将兼容义务组合成多个小型 witness worlds。
6. 实际执行每个 world，确认反例是否真实存在。
7. 失败时只围绕未满足义务进行有界定向补数。
8. 让结构、造数、变异、归因共用同一差异标识和证据链。
9. 逐步迁移现有 59 个探针，保持旧入口兼容并防止能力回退。
10. 在 2～4 GiB cgroup 硬限制内完成分层、多来源、大规模回归。

## 4. 第一阶段：可信 Schema 与查询作用域

### 4.1 必须完成

- Spider 使用真实数据库 Schema 元数据，禁止仅用 SQL 正则猜表结构；
- 区分物理表、CTE、派生表、子查询别名和表函数；
- 按查询块维护 CTE 和别名作用域；
- 解析限定列并将别名映射回物理表；
- 识别列类型、主键、外键、NULL 约束和唯一性信息；
- 检查 SQL 引用的物理表和列是否存在；
- 多条 SQL、DML 和不可执行教程片段在进入造数器前隔离；
- 无法 SQLite 兼容执行的方言进入原生引擎或明确标记能力边界；
- Schema 资格检查失败不能被统计成造数失败。

### 4.2 目标数据结构

```python
@dataclass(frozen=True)
class ColumnRef:
    relation: str
    column: str
    query_scope: str

@dataclass
class QueryScope:
    id: str
    parent_id: str | None
    physical_tables: dict[str, str]
    ctes: set[str]
    derived_relations: set[str]
    referenced_columns: set[ColumnRef]

@dataclass
class SchemaQualification:
    scopes: list[QueryScope]
    physical_tables: set[str]
    missing_tables: set[str]
    missing_columns: set[ColumnRef]
    executable: bool
    boundary_reason: str | None
```

## 5. 第二阶段：Distinguishing Obligation IR

所有策略先将 AST 差异编译为语义目标，不再直接根据 SQL 文本改写数据。

```python
@dataclass
class DistinguishingObligation:
    id: str
    diff_id: str
    diff_type: str
    clause: str
    knowledge_point_id: str | None
    required_tables: set[str]
    required_columns: set[ColumnRef]
    minimum_rows: dict[str, int]
    hard_constraints: list[Constraint]
    soft_constraints: list[Constraint]
    conflicts_with: set[str]
    success_predicate: str
    estimated_cost: int
```

### 5.1 核心义务映射

| SQL 差异 | 必须生成的数据条件 |
|---|---|
| `> c` 与 `>= c` | 至少一行值恰好为 `c` |
| `AND` 与 `OR` | TT、TF、FT、FF 真值组合 |
| INNER 与 LEFT JOIN | 左表至少一条无匹配记录 |
| JOIN ON 列错误 | 正确列相等、错误列不等 |
| GROUP BY 列错误 | 一列相同、另一列不同 |
| `COUNT(*) > 3` 与 `>= 3` | 至少一个分组恰好 3 行 |
| UNION 与 UNION ALL | 两个分支产生相同投影元组 |
| INTERSECT 与 UNION | 左独有、右独有和交集元组 |
| NOT IN 与 NOT EXISTS | 子查询含 NULL 和非匹配值 |
| RANK 与 ROW_NUMBER | 窗口排序列出现并列 |
| 有无 PARTITION BY | 至少两个分区且局部/全局排名不同 |
| CASE ELSE 缺失 | 至少一行不命中任何 WHEN |
| 相关子查询条件错误 | 外层至少两行经过不同相关路径 |
| 递归 CTE 差异 | 根、正常子节点、孤儿和重复路径 |

每个 ASTDiff 必须具有稳定 `diff_id`。结构、造数、变异、归因均引用该 ID。

## 6. 第三阶段：声明式约束与单元格所有权

现有探针中的直接写入：

```python
row[column] = value
```

逐步迁移为：

```python
CellConstraint(
    table="employee",
    row_slot="boundary_row",
    column="salary",
    relation="equals",
    value=50000,
    owner="comparison_boundary_probe",
    obligation_id="diff_3",
    priority=80,
    locked=True,
)
```

### 6.1 策略必须声明

- 触发条件；
- 读取的表、列和行角色；
- 写入的单元格；
- 最小行数；
- 硬约束和软约束；
- 冲突策略；
- 依赖策略；
- 预期执行差异；
- 估算成本；
- 验证函数。

### 6.2 合并规则

- 硬约束冲突：拆分 world，禁止覆盖；
- 锁定单元格：后续策略不可静默写入；
- 同值约束：合并所有者；
- 兼容范围约束：取交集；
- 不兼容范围约束：拆分 world；
- 软约束冲突：按优先级和成本选择；
- 修复步骤不得修改与自身义务无关的锁定单元格。

## 7. 第四阶段：WitnessSuite 与 Planner

```python
@dataclass
class WitnessWorld:
    id: str
    obligation_ids: list[str]
    constraints: list[Constraint]
    database: dict[str, list[dict[str, object]]]
    diagnostics: list[str]

@dataclass
class WitnessSuite:
    worlds: list[WitnessWorld]
    obligations: list[DistinguishingObligation]
    uncovered_obligations: list[str]
```

### 7.1 Planner 职责

1. 构建义务依赖图和冲突图；
2. 优先组合写集不相交或约束兼容的义务；
3. 冲突义务分配到不同 world；
4. 计算每个 world 的最小行数；
5. 控制每表行数和总组合成本；
6. 禁止无界笛卡尔积；
7. 为每个 world 生成确定性 seed；
8. 保留义务到 world 的可追踪映射。

### 7.2 资源边界

- 普通场景每表 3～16 行；
- 窗口、递归和复杂聚合每表最多 32 行；
- 默认每题最多 8 个 worlds；
- 每义务最多 8～16 次定向搜索；
- 单次查询固定超时；
- 递归 CTE、笛卡尔积和复杂原生执行使用独立子进程；
- 完整批次运行在 2～4 GiB cgroup 内存上限下；
- 不依赖可能瞬时申请大量内存的通用 SMT 求解器。

## 8. 第五阶段：固定策略阶段

唯一 planner 按以下阶段运行，删除注册表与固定调用的重复执行：

1. Schema 和查询作用域解析；
2. 表拓扑与主外键布局；
3. 基础类型值域；
4. WHERE、比较、逻辑和 NULL 边界；
5. JOIN 匹配和悬空元组；
6. GROUP BY、HAVING 和聚合；
7. 子查询和相关路径；
8. 集合操作；
9. 窗口函数；
10. CTE 和递归 CTE；
11. DISTINCT 和重复元组；
12. ORDER BY、LIMIT 和 OFFSET；
13. CASE、函数参数和投影区分；
14. 约束一致性检查；
15. 实际执行验证。

## 9. 第六阶段：执行反馈和定向补数

每个 world 都必须实际执行：

```python
standard_result = execute(standard_sql, world)
student_result = execute(student_sql, world)
distinguished = standard_result != student_result
```

若没有区分：

1. 找到未满足义务；
2. 检查约束是否落地或被覆盖；
3. 只调整该义务相关表和列；
4. 扩大临界值附近的小候选域；
5. 生成新的独立 world；
6. 达到预算后保存最小失败证据。

等价 identity 对照必须执行成功并保持相同结果；解析、Schema、方言或执行引擎失败必须
单独归类，不能伪装成等价性结果。

## 10. 结构、造数、变异、归因统一证据链

```text
ASTDiff: comparison_operator_changed (diff_3)
→ Obligation: salary = 50000
→ Witness: world_2 employee.salary = 50000
→ Student result differs
→ Mutation: 将学生 >= 替换为标准 >
→ Mutated result恢复
→ Attribution: 比较边界错误
```

完整链路必须验证：

- 结构识别了具体差异；
- 造数为该差异生成了反例；
- 原学生 SQL 在至少一个 world 中失败；
- 替换对应差异后结果恢复；
- 归因命中同一知识点；
- 不相关差异没有被误归因。

## 11. 探针有效性证据

每次运行至少记录：

```json
{
  "obligation_id": "diff_3",
  "probe": "comparison_boundary_tristate",
  "activated": true,
  "constraints_satisfied": true,
  "overwritten": false,
  "world_id": "world_2",
  "standard_result": [],
  "student_result": [],
  "distinguished": true
}
```

统计维度：

- 激活数；
- 约束成功落地数；
- 冲突拆分数；
- 被覆盖数（目标必须为 0）；
- 实际区分数；
- 定向补数次数；
- 未覆盖义务；
- 各来源和各知识点覆盖量。

## 12. 现有 59 个探针迁移顺序

1. 比较、NULL、LIKE、IN、BETWEEN 和逻辑运算；
2. JOIN、外连接、缺失 JOIN 和 Self JOIN；
3. GROUP BY、HAVING 和聚合；
4. DISTINCT、ORDER BY、LIMIT/OFFSET；
5. UNION、UNION ALL、INTERSECT、EXCEPT；
6. 普通子查询、相关子查询和嵌套 membership；
7. 窗口分区、排序、排名、别名过滤和 LAG；
8. 普通 CTE、递归 CTE、孤儿、环路和重复路径；
9. CASE、投影、函数参数和方言专项。

迁移方式：

1. 为旧探针增加读写追踪适配器；
2. 建立变更快照，记录探针前后单元格差异；
3. 标记同一单元格的多策略写入；
4. 将高频冲突探针改为约束声明；
5. 新旧模式双跑并比较结果；
6. 新模式达到门槛后再删除旧直接调用。

- 结果明确区分支持、已知边界、语料不合格、引擎失败和真正系统缺陷。

## 15. 执行优先级

```text
真实 Schema/作用域
→ Obligation IR
→ 单元格锁与冲突检测
→ 多 Witness World
→ 执行反馈
→ 逐步迁移现有策略
```

首轮不直接扩大到 10,000 条。每个阶段按以下规模晋级：

```text
专项单测
→ 历史缺陷回放
→ 100 条多来源分层样本
→ 500 条
→ 1,000 条
→ 10,000 条分批运行
```

任何阶段出现内存异常、策略覆盖或新的失败签名，都先修复并回放，再扩大规模。
